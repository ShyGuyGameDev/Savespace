# Decisions log

Decisions made autonomously while building. Newest at the bottom.

1. **Toolchain (verified 2026-11-10 via `npm view`):** Electron 45.3, electron-vite 6.0 (peer: Vite 6–8), Vite 8, React 19.3, TypeScript (see #12), Tailwind 4.3, Zod 4.6, Drizzle ORM 0.45 / drizzle-kit 0.31, better-sqlite3-multiple-ciphers 13.0, Vitest, Playwright 1.65, electron-builder 26.18.
2. **electron-vite over vite-plugin-electron.** Both are active (electron-vite 6.0.0 published 2026-10-14; vite-plugin-electron 1.2.0 on 2026-10-31). electron-vite gives a first-class three-target config (main/preload/renderer) with sandbox-friendly CJS preload output, which maps 1:1 onto the required `src/main`, `src/preload`, `src/renderer` layout. vite-plugin-electron is a lower-level plugin that would need that wiring by hand.
3. **Window titles via System Events (Accessibility), never CGWindowList names.** See adapter-research.md. No Screen Recording permission is requested anywhere.
4. **Safari tab capture is opt-in** because Safari can't report private windows. Restore into Safari works regardless.
5. **Terminals restore via `open -a <Terminal> <dir>` / Warp URI**, never AppleScript `do script` or iTerm `write text`.
6. **VS Code-family capture reads a copy** of `state.vscdb` placed in Savespace's own temp dir, opened read-only, so the editor's live database is never opened by us.
7. **Ollama default model by RAM:** ≤ 8 GB → `llama3.2:3b` (~2 GB, leaves headroom on 8 GB Macs); 9–16 GB → `gemma4:e2b` (4.6 GB); 17–32 GB → `gemma4:e4b` (6.6 GB); > 32 GB → `gemma4:12b`. Tags verified on ollama.com/library on 2026-11-10. This Mac has 8 GB, so the default is `llama3.2:3b`. _(Superseded by #36: Ollama is now built in and reached on a random loopback port.)_
8. **Encryption:** better-sqlite3-multiple-ciphers with default cipher (ChaCha20-Poly1305 / sqleet), a 32-byte random key generated on first run, encrypted with `safeStorage` and stored as `db.key.enc` in the app data dir. If `safeStorage` is unavailable (should not happen on macOS), the app refuses to create an unencrypted DB and shows an error.
9. **Drizzle migrations** are generated by drizzle-kit into `src/main/db/migrations` and applied at startup with `drizzle-orm/better-sqlite3/migrator`. They're bundled as extra resources in the packaged app.
10. **Global hotkeys:** `⌥⌘Space` opens the palette and `⌥⌘S` runs Checkpoint now. Both are configurable in Settings. (`⌘Space` is Spotlight and `⌥Space` is common in other launchers.)
11. **Arrange windows** (optional, off by default) uses System Events `set position`/`set size` on a matched window of the target app. These are the only `set` verbs allowed, and only in templates flagged `arrange: true`, which run only when the setting is on.
12. **TypeScript 6.0.x, not 7.0.** npm `latest` is 7.0 (the native port), but typescript-eslint 8.72 requires `<6.1.0`. Pinned `~6.0.3`.
13. **`ELECTRON_RUN_AS_NODE` is unset in run scripts.** Some editor terminals (including the VS Code extension host this was built in) export `ELECTRON_RUN_AS_NODE=1`, which makes Electron boot as plain Node (`app` undefined). `npm run dev`/`start`/`test:e2e` use `env -u ELECTRON_RUN_AS_NODE`. Conversely, unit tests deliberately _set_ it so Vitest runs on Electron's own Node (same ABI as the shipped native module).
14. **Single renderer entry with hash routes** (`#/`, `#/palette`, `#/popover`, `#/onboarding`) rather than four HTML entries. One bundle, one CSP, and the windows share the cached JS.
15. **`better-sqlite3-multiple-ciphers` ships N-API prebuilds** (`prebuilds/darwin-arm64.node`), so one binary works under both Node and Electron. Verified: encrypted file has no plaintext, can't be opened without the key, and reads back with it.
16. **`better-sqlite3` is an npm alias for `better-sqlite3-multiple-ciphers`** (`"better-sqlite3": "npm:better-sqlite3-multiple-ciphers@^13"`). Drizzle's driver imports `better-sqlite3` by name, so the alias ensures the SQLite3MultipleCiphers build is the only SQLite binary in the app, and `@types/better-sqlite3` types it.
17. **SafeExec + script registry were built in Phase 3, not Phase 6**, because permission detection already needs to run `osascript` probes, and the open-only rule says _all_ process execution goes through SafeExec. Phase 6 extends it with the restore side.
18. **Automation consent is requested only from apps that are already running**, using a read-only probe (`app.probe`). Asking a JXA `Application()` that isn't running would launch it, which Savespace must not do unasked.
19. **`lsappinfo front`** (no permission required) is the degraded-mode source for the frontmost app when Accessibility is denied.
20. **`SAVESPACE_USER_DATA`** env var relocates all app data. Used by e2e tests so they never touch the real profile.
21. **Adapter files are grouped by mechanism** (e.g. `browsers.ts` holds Chrome/Brave/Edge/Vivaldi/Chromium/Arc/Safari via one factory; `vscode-family.ts` holds VS Code/Insiders/Cursor/Windsurf). Each is still a single exported `AppAdapter` registered with one line in `adapters/index.ts`. A brand-new app is one file + one line, as required. One file per app would have duplicated ~150 lines per Chromium browser.
22. **Window frames and git state are handled by kind-based adapters** (`arrange`, `git`), so every app gets optional arrangement without per-adapter code, and git state is shown as context but never "restored" (no checkout).
23. **Finder `.DS_Store`:** the live fixture test showed Finder writes a `.DS_Store` (view settings) next to a folder it opens. That's Finder's behaviour for the allowed "open a folder" action, not a Savespace write. The test allows exactly that file name, only in live mode, and fails on any other created, deleted, or modified file.
24. **Slack desktop** exposes only the selected workspace (from its own `root-state.json`), so the Slack adapter is _partial_: it reopens the workspace (`slack://open?team=`). Exact channels/threads come from `app.slack.com` URLs when Slack was used in a browser, which are mapped to `slack://channel?team=&id=`.
25. **Terminal cwd** comes from the tab's tty → shell pid (`ps -o pid=,comm= -t ttysNNN`) → cwd (`lsof -a -d cwd -p PID -Fn`). Both are read-only and allowlisted with exact argument shapes.
26. **Ollama is called only from the main process through `guardedFetch`**, which refuses every host except the bundled engine's current loopback port (http only; originally `127.0.0.1:11434`, see #36) and the opt-in Google hosts (https only), with `redirect: 'error'`. The renderer can't make any network request (CSP `connect-src 'self'` + `webRequest` blocking).
27. ~~Savespace never pulls models itself.~~ Superseded by #36.
28. **Summaries are post-filtered** (`cleanSummary`): max 3 sentences, markdown stripped, and any sentence that starts like advice/next steps/decisions/questions is dropped, so the "What you were doing" rule holds even if the model drifts.
29. **Embeddings (optional):** if `nomic-embed-text` is pulled in Ollama, near-duplicate new-project suggestions (cosine ≥ 0.88) are folded together. Without it, nothing changes.
30. **Async `safeStorage`.** Electron 45 deprecates the synchronous `safeStorage` calls, so the app uses `isAsyncEncryptionAvailable` / `encryptStringAsync` / `decryptStringAsync` and re-encrypts the key file when macOS reports `shouldReEncrypt`. Unit tests use a sync stub key provider.
31. **App entries always use the generic launcher**, even for apps that have a deep adapter, so "open/focus VS Code" is a real step in the restore plan rather than context.
32. **Delete-all also wipes settings**, so Savespace returns to the welcome flow. Built-in exclusions (password managers etc.) are re-seeded immediately so protection never lapses.
33. **E2E tests run with `SAVESPACE_DRY_RUN=1`** (SafeExec validates and records but executes nothing) and `SAVESPACE_E2E_SEED=1` (demo data). The live open-only proof is the fixture-hash integration test.
34. **Packaging:** electron-builder 26 → `release/Savespace-<version>-arm64.dmg` (Apple Silicon only; this Mac is arm64. Add `x64` to `mac.target.arch` for Intel). `identity: null` produces an unsigned (ad-hoc) build. Hardened runtime and the `com.apple.security.automation.apple-events` entitlement apply automatically once you sign with a Developer ID. `NSAppleEventsUsageDescription` is in Info.plist so macOS can show the Automation prompt. `minimumSystemVersion` is 15.0 (current macOS 27 minus two majors, per the target matrix; macOS 15 → 26 → 27).
35. **`process.umask(0o077)`** at startup so SQLite's WAL/SHM side files are owner-only like the DB itself.
36. **Local AI is built in (supersedes #7's "install Ollama" and #27).** The Ollama engine **v0.40.12** (MIT) is downloaded at build time by `scripts/fetch-ollama.mjs` and SHA-256-verified. Only `ollama`, `llama-server` and the licences are kept: 93 MB instead of 580 MB. The Intel-only libraries and the 440 MB Apple MLX backend are dropped, since the default models are GGUF and run on Metal via llama.cpp (verified live on this M3). It ships in `Contents/Resources/ollama`, which adds ~26 MB to the `.dmg`. Savespace starts it on launch and downloads the RAM-appropriate model automatically into its **own** data folder (`ai/models`, engine `HOME` = `ai/home`). That writes only inside Savespace's data directory, so it's consistent with the open-only rule. MLX-format tags (`*-mlx`) aren't supported in this build.
37. **Egress gate for the engine.** `OLLAMA_NO_CLOUD=1` doesn't stop the engine's periodic "model recommendations" fetch, so all engine traffic is forced through a local CONNECT proxy. The proxy only opens during a Savespace-initiated download, only to `registry.ollama.ai` and `<32-hex>.r2.cloudflarestorage.com`, port 443. Those hosts were observed with a logging proxy during a real pull. Blocked attempts are audit-logged (rate-limited to one per minute).
38. **Pinned an older stable engine.** v0.40.16 was one day old, so v0.40.12 (two weeks old) is pinned. Upgrading means changing `OLLAMA_VERSION` and `SHA256` in `scripts/fetch-ollama.mjs`, then re-running the AI-engine tests.
39. **Users who already run Ollama** are unaffected. Savespace uses its own engine and port and never reads or writes `~/.ollama`.
40. **Apple's on-device AI first, small download second.** Savespace ships a tiny Swift helper (`native/apple-ai/main.swift` → `resources/apple-ai/savespace-apple-ai`, built by `scripts/build-apple-ai.mjs` with the Command Line Tools; target macOS 15 so it reports "osTooOld" instead of crashing on older systems). It calls Apple's FoundationModels `SystemLanguageModel.default` (on-device only; API names checked against the SDK's `.swiftinterface`). Live on this Mac (M3, macOS 27.0.1): status `available`, summaries in 3–9 s, no download. With source **Automatic** (default), if Apple's model is available the Ollama engine is never started and nothing downloads; otherwise the engine starts and quietly fetches the fallback while plain summaries cover the gap.
41. **Fallback model is `llama3.2:3b` for every Mac (2.0 GB, ~45 s on this connection)**, replacing the RAM-scaled defaults (up to 9.5 GB). Smaller models were tested and rejected for inventing facts (see the safety audit, caveat 6). Larger models remain selectable in Settings.
42. **Shared instructions tuned for small models:** name files not full paths, name only listed files, no advice. The git section of the fact sheet is labelled "Git repository (not a file)".
43. **New setting `aiProvider`** (`auto` | `apple` | `downloaded`); summaries record their source (`apple` | `ollama` | `template`) and the UI badges them.
44. **Chrome-family profiles (accounts).** The scripting dictionary has no profile property, so each window's profile is inferred read-only. `Local State` gives folder → name, and each profile's newest `Sessions/Session_*` file holds its open-tab URLs. A window goes to the profile whose session contains most of its tabs; ties or no match mean no profile, so the old behaviour applies. Restore runs the browser's own executable with exactly `--profile-directory=<Default|Profile N|Guest Profile> <http(s) URL>` (SafeExec validator), which hands the URL to the running browser as a new tab in that profile. Existing tabs in that profile are focused instead (`chromium.focus-tab` re-checks the URL first). Covered by unit tests with fake profile files; **not verified live**, because the build environment's sandbox can't read Chrome's folder.
45. **Checkpoints save only what's in use and related (`checkpoints/relevance.ts`).**
    - **Kept:** items matching the project's signals (its repo, folders, sites).
    - **Dropped:** items never in front during the session (from the once-a-minute activity samples; at least the last 2 hours, or since the previous checkpoint, max 8 h). With fewer than 3 samples, everything open is a candidate.
    - **Judged by the AI:** the remaining in-use items. The question is phrased as "which are **clearly unrelated**?", so doubt keeps an item. Bare apps are judged by their window title (e.g. the Slack channel). Without a project, the most-used item defines the work.
    - **No AI or an unusable answer:** in-use items are kept.
    - **Follow-ups:** apps, window positions and git state follow the kept items. Left-out items are listed in the audit log ("Left out N open items…").
    - **Verified live** with Apple's on-device model, 4/4 runs: code file, Jira ticket, Stack Overflow answer, Redis docs and the Slack project channel kept; a music video and a shopping page dropped. Asking "which are related?" instead had wrongly dropped the Redis docs and Slack.
46. **Merge and split removed (user request).** Gone from the project menu, the Suggestions inbox (including "Add to existing…"), inference (only "new project" suggestions are made; older merge/split rows are ignored), the IPC contract and the store.
47. **Editing instead.**
    - **Projects:** `projects:update` (name, colour, signals; folders and websites can be added or removed in plain words) and `projects:delete` (its checkpoints and activity are kept, unassigned).
    - **Checkpoints:** `checkpoints:update` (edit the "What you were doing" text, remove saved items by index). Changing a checkpoint's project already existed.
    - All edits are audit-logged.
48. **The AI download asks first.** On Macs without Apple's on-device AI, the intro asks "Download the AI model?" (about 2 GB, downloads in the background, shows where it's saved and where it comes from), with Yes / No thanks. Skipping that step, or finishing the intro without answering, counts as yes. Nothing downloads during the intro before an answer. "No" can be reversed in Settings → Local AI → Download. Setting: `aiDownloadConsent` (`unasked` | `yes` | `no`), checked by `aiDownloadAllowed()`.
49. **The window never scrolls, only its panels.** `html, body { overflow: hidden }` stops the page itself from scrolling. Every scroll container is `position: relative`, so visually hidden (absolutely positioned) labels can't stretch the page. That was the cause of the Settings window scrolling past its bottom by 184 px.
50. **Checkpoint now can't be spammed.** Every Checkpoint button and ⌘N share one "saving" state per window (greyed out, "Saving…"). The main process also hands repeat requests the checkpoint already being made (button, palette, tray, global hotkey), so rapid clicks produce exactly one checkpoint.
51. **Ad-hoc signing for builds without a Developer ID (fixes "Savespace.app is damaged").** With `identity: null`, electron-builder skipped signing. The app kept Electron's original linker signature, which doesn't cover Savespace's added files (`codesign --verify`: "code has no resources but signature indicates they must be present"). macOS treats a downloaded app with a broken seal as tampered and shows "damaged" with no way to open it. Now `identity: '-'` signs the whole bundle ad-hoc (verified: "valid on disk", 99 sealed files, also after copying out of the `.dmg` with a Chrome-style quarantine flag). Downloads then get the normal "Apple could not verify…" prompt and can be opened once via System Settings → Privacy & Security → Open Anyway. `hardenedRuntime` is off for ad-hoc builds (it's meant for Developer ID signing; with an ad-hoc signature library validation can block the app's own frameworks). Only a paid Developer ID plus notarization removes the warning entirely (SETUP_GUIDE 11.2).
52. **No capture (and so no macOS permission prompts) until the intro is finished.** Previously the capture scheduler started at launch, so macOS's "wants access to control System Events" prompt could appear before the intro had explained it. Now ticks and power events (sleep/lock/quit) do nothing until `onboardingComplete`, and capture starts as soon as the intro is done. The intro's own **Ask** buttons are the only thing that triggers these prompts before then.
53. **Users only ever see "Savespace".** No user-facing text (app UI, setup guide) mentions the underlying framework: the dev-mode "(or … while developing)" note and the technical hotkey hint were removed. The packaging config was renamed to `packaging.yml` (`npm run dist` passes `--config packaging.yml`).
54. **Per-app controls on the Apps page.**
    - **Save what's open** (`appsCaptureOff`): the app is dropped before capture, so Savespace neither reads it nor sends it requests. Git off skips repository checks.
    - **Reopen when resuming** (`appsRestoreOff`): its items are planned as "skip", with the reason shown in Preview restore.
    - **macOS Automation:** "Allow…" asks right there, opening the app quietly in the background if needed. Apps can't revoke a macOS permission themselves, so "Turn off…" and "Allow in System Settings…" open the Automation pane with a one-line instruction.
    - **Remembered answers:** permission answers are now persisted (`automationStates`) instead of resetting each launch.
    - **Not listed:** window arrangement (it's in Settings) and Google (Settings → Connectors).
55. **Projects are made of apps (replaces the folders/websites editor).** Edit project → **Add app** (installed apps, with bundle ids read read-only via an allowlisted `plutil -extract CFBundleIdentifier raw -o - <App>.app/Contents/Info.plist`). Each app can pin items by app type: browsers → tabs (URLs); code editors → folders and files; Finder and terminals → folders; document apps → files; other apps → just the app.
    - **Adding items:** "Add from what's open now" (a read-only capture of that app), a native folder/file picker, or a pasted address.
    - **Signals:** a project's signals are learned ones plus ones derived from its apps (`app:<bundle id>`, the pinned hosts and paths), recomputed on save. Activity samples now include `app:<front app>`.
    - **Checkpoints:** with chosen apps, only those apps are kept, pinned items always are, and the rest of a chosen app's items go through the usual in-use + AI check.
    - **Restore:** pinned items are added to the plan if the checkpoint lacks them.
    - **Database:** migration `0001_project_apps` adds `projects.apps` (default `[]`).
56. **Look again always answers.** `suggestions:refresh` now returns `{ suggestions, found, source, message }` and tries, in order:
    1. recent activity under the normal rules (3 samples across 2 windows);
    2. a looser pass (2 samples, 1 window);
    3. what's open right now (its repos, folders and sites), then the app in front (`app:<bundle id>`; accepting it creates a project made of that app);
    4. otherwise a message: either how many suggestions are still waiting, or what to open first.
    Dismissed ideas are never brought back. The result shows as a status banner under the header.
57. **Checkpoint now moved into the timeline header.** The button above the sidebar is gone. The timeline header has **Checkpoint now** on All checkpoints and on each project page, where it saves a checkpoint for that project (⌘N does the same for the page you're on). All buttons share one busy state and grey out while saving. The menu-bar popover and global hotkey are unchanged.
58. **Deleting a checkpoint asks first.** A confirmation shows the checkpoint (project, time, summary, number of items), says plainly that files, tabs and apps aren't touched, and focuses **Cancel** by default so Return can't delete by accident. Escape or clicking outside cancels. Errors show inline, and a toast confirms the delete.
59. **"Only restore these apps" (per project, shown once a project has apps; on by default, which matches entry 55).**
    - **On:** checkpoints keep only the chosen apps, and in an app with pinned items only those items. Restore skips anything else in older checkpoints, with the reason shown.
    - **Off:** the chosen apps and pinned items are always kept, plus anything else that was in use and judged related by the usual in-use + AI check.
    - **Database:** migration `0002_only_apps` adds `projects.only_apps` (default 1).
60. **The local AI files new checkpoints under a matching project.** When a checkpoint is made without a chosen project and the rules (matching repos, folders, sites) find none, the local AI gets two things: a short description of each active project (its apps and pinned items, repos, folders, sites, and its last summary) and what you were working on (the focused item first, then recently used items and window titles). It replies with one project number or NONE. The checkpoint is filed only on a single clear answer. NONE, an unreadable answer, more than one number, or no AI leaves it unassigned. A confident rule match or an explicitly chosen project is never second-guessed. Each AI filing is written to the audit log ("Filed under …, judged by …"), and you can still move a checkpoint with the project menu on its detail page. Everything runs on-device (Apple's model or the downloaded one) and follows the AI on/off and source settings. Tested with stubbed answers, and against the real Apple model on this Mac: about 4.5 s, correct on a matching and a non-matching case.
61. **AI filing is deliberately strict: leaving a checkpoint unassigned beats filing it wrong.** (Tightens entry 60.)
    - **What counts as a match:** the AI may pick a project only when a specific item ties the work to it: the same website, repo, folder or file, or a clearly named shared topic. The same kind of app, an inbox, chat, a search page or a loosely similar subject doesn't count.
    - **Second check:** a separate yes/no question must come back as a plain YES.
    - **Bare apps:** if only bare apps are open, the AI isn't asked at all.
    - **Real-model check (Apple model on this Mac):** a Lisbon hotel and map was filed under "Trip to Lisbon" (about 5–8 s for both questions). A recipe, a Paris hotel, a Gmail inbox and a file from a different codebase were all left unassigned.
62. **Tracking on/off is always visible and one click away.**
    - **Dashboard:** a power button sits in the top-right corner of every page, with "Tracking on" (green) or "Tracking paused" (amber) to its left. Page headers leave room for it.
    - **Menu-bar dropdown:** the unlabeled power icon is replaced by a status row near the top: "Tracking is on / Checkpoints save automatically" or "Tracking is paused / No automatic checkpoints", with a **Pause tracking** / **Resume tracking** button. These labels avoid clashing with the projects' Resume buttons.
    - **Icon:** the menu-bar icon's tooltip and right-click menu also show the state, and the right-click menu can toggle it.
    - **What pausing does:** it uses the existing `captureEnabled` setting, so activity sampling, automatic checkpoints (idle, project switch, end of day, sleep, lock, quit) and project detection all stop. The "You're working on …" context is hidden. Each change is written to the activity log.
    - **Still allowed while paused:** checkpoints you start yourself (Checkpoint now), since you ask for those directly.
